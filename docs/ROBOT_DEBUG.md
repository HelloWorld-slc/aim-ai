# 机器人连接与调试

AIM AI 0.4.0 将 [VEX-AIM-MCP](https://github.com/flashzdw/VEX-AIM-MCP) 的部分能力整合到 VS Code 的「机器人」页。通信使用官方 AIM WebSocket 库，通过 Wi-Fi 读取状态并测试有限动作。

**当前发布为预览版：模拟和插件流程已验证，实机兼容性仍待验收。** 这条连接建立的是远程调试会话，不能据此认定已下载的学生程序运行正确。官方库连接时会初始化远程程序并重置会话朝向；先结束其他控制程序。

## 1. 准备环境

- 桌面 VS Code 1.96+、AIM AI 0.4.0+。
- Python 3.10+；安装后可重新打开 VS Code。路径特殊时设置 `aimAI.pythonPath`。
- 点击「机器人 → 安装调试环境」。插件在自己的数据目录创建虚拟环境，安装固定版本的 MCP 和 WebSocket 依赖，不向学生项目写入依赖。
- 电脑和机器人能够通过同一网络相互访问。AI 模型另需互联网；本地状态读取不需要模型 API。

安装过程可取消。网络受限时先解决 Python 包下载，再重试。支持的 Python 版本以持续集成和 [测试记录](TESTING.md) 为准；尚未覆盖每个操作系统组合。

## 2. 第一次为机器人配 Wi-Fi

### 先连接机器人热点

1. 在机器人屏幕进入 **Settings → Radio → Access Point**。
2. 启用 Access Point；图标变绿后再点进去。
3. 查看屏幕上的 Wi-Fi 名称（SSID）、密码和 IP。默认 IP 为 `192.168.4.1`，以实际显示为准。
4. 在 Windows 的 Wi-Fi 列表连接该 SSID，输入机器人屏幕显示的密码。
5. 浏览器打开 `http://192.168.4.1`；如果机器人使用其他 IP，替换为对应地址。

电脑切换到机器人热点时会离开原 Wi-Fi，可能暂时无法访问模型服务。只做本地控制时可以保持这种直连方式。配图见 [官方首次连接教程](https://api.vex.com/aim/home/websocket/wifi_setup/connection_initial.html)。

### 推荐：让机器人加入课堂 / 家庭 Wi-Fi

1. 在上一步打开的设置网页勾选 **Join existing network**。
2. 填写准备让机器人加入的 Wi-Fi 名称和密码，点击 **Save**。官方文档目前注明两项各最多 20 个字符。
3. 机器人会退出热点模式并加入该网络。
4. 把电脑重新连接到同一网络。
5. 点击机器人屏幕的 **Station** 图标，查看路由器分配的新 IP。
6. 在插件「机器人」页选择 **真实机器人（Wi-Fi）**，输入这个新 IP，点击 **保存连接设置**。

Station 模式使用 DHCP；换网络或路由器重新分配后，IP 可能变化。无需把 Wi-Fi 密码交给模型或插件，插件只保存机器人 IP。[官方 Station 模式图解](https://api.vex.com/aim/home/websocket/wifi_setup/connection_sta.html)

课堂宜使用专用网络。部分访客网络禁止设备互访，即使电脑和机器人名称相同也可能无法连接。确认能访问机器人设置网页，再排查固件与占用的控制会话。

## 3. 按需自动连接

「AI 按需自动连接，无需再次确认」默认开启；生效前必须完成调试环境安装并保存 IP / 模式。

- AI 只有实际调用读取状态或提出测试工具时才发起连接，普通聊天不会先连接。
- 已连接时复用会话。连接失败后，同一轮任务只尝试一次；修正 IP 后重新提问即可。
- 自动连接成功后，AI 可读取电量、位置、朝向、停止状态，以及有限的足球 / 桶识别结果。
- 关闭该开关后，可以手动连接，并在编程页勾选「本次允许 AI 读取机器人状态、提出测试建议」。
- 自动连接会新建远程调试会话，并具有前述初始化行为。

示例提问：

> 看一下机器人当前电量和朝向，解释这些信息能帮助我排查什么问题。

## 4. 执行单步测试

手动选择测试，或让 AI 提出方案，然后在机器人页点击 **执行本次测试 / 执行建议测试**。

| 测试 | 可用范围 |
| --- | --- |
| 直行 | 1–200 mm |
| 右转 | 1–90° |
| 速度 | 10–30% |
| AI 测试建议有效期 | 2 分钟 |

模型工具只能提出方案，不能自行执行运动、下载或运行项目。动作前确认地面区域空旷。测试约 10 秒超时，另有本地停止计时；「停止 / 取消」会发送停止请求，断网时不能保证机器人收到。

结果包含测试前后的状态、用时、位置变化和朝向变化。点击 **让 AI 分析结果**，才会把手动测试摘要连同当前程序发送到所选模型。一次接口测试可辅助排查方向、单位和连接问题，不证明正方形或足球策略已经整体通过验证。

## 5. 没有机器人时使用模拟演示

选择 **模拟演示** 并保存设置或点击连接。模拟提供固定电量、简单位移和空视觉列表，界面和模型收到的内容均标明模拟来源，不打开机器人网络连接。

适合检查插件交互、AI 工具调用和课堂演示流程；不模拟惯性、摩擦、碰撞或真实足球识别。

## 6. 费用与数据

- 安装、连接、手动读取、单步测试不调用模型，也不消耗模型 token。
- AI 辅助每轮最多 3 次模型请求、2 次状态读取，连接失败只尝试一次。
- 每份状态摘要最多 8,000 字符；视觉只返回少量目标结构，不上传摄像头图像或音频。
- API 计费仍由所选服务商决定；工具定义、当前源码、历史和资料也会占用上下文，不能把次数限制理解为固定 token 费用。

## 排查连接失败

| 现象 | 先检查 |
| --- | --- |
| 浏览器打不开机器人 IP | 电脑是否在正确网络、是否使用 Station 新 IP、网络是否隔离设备 |
| 设置网页能打开但调试失败 | 结束其他控制会话，确认固件，重新连接；插件等待超时后会结束后台进程 |
| 状态过期 | 机器人供电、Wi-Fi 信号；重新连接后再读取 |
| 上次动作未正常完成 | 观察并停止机器人，重新建立会话后再测试 |
| 模型回答正常但没有连接 | 只有调用机器人工具时才连接；确认已保存设置并开启自动连接 |
| 模拟结果与实机不同 | 模拟只验证软件流程，切换真实机器人后需要重新记录结果 |
